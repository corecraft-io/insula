# 架构决策记录（ADR）

[English](README.md) | 中文

本目录存放 Insula 的架构决策记录。一条 ADR 记录的是**不显然**、**只做一次**、否则会被反复
重议或被静默推翻的决定。判据不是「这件事重要吗」，而是「日后会不会有人纳闷它为什么是这样，
或者没注意到就把它改回去了」。

## 格式

`NNNN-<slug>.md`，四位数字，**永不复用、永不重编号**。每条记录用同样五节：

```markdown
# ADR-NNNN <标题>

- 状态：Accepted | Proposed | Superseded by ADR-NNNN | Deprecated
- 记录日期：YYYY-MM-DD
- 落实于：<包>

## 背景
为什么需要一个决定。是世界的哪个性质（或 cordis 的哪个性质）逼出了它。

## 决定
决定本身，写成指令，不写成讨论。

## 后果
哪些事变容易了。哪些事变难了。**「更困难」那一半是必填的**——一条不写代价的 ADR 是
一份推销材料。

## 落实位置
这个决定在代码里的可见处。写**符号名，不写行号**：行号会漂移，符号不会。

## 更新
可选，带日期。决定之后发生了什么变化。**不要改写原文**——ADR 的价值有一半正在于它记录了
当时相信的是什么。
```

**行号会漂移，符号不会。** 引用函数与类型，不要引用 `file.go:123`。

## 七条之间的关系

它们不是彼此独立的。单独去读之前，有三组交接值得先知道：

- **0001 → 0002 → 0007。** 0001 把数据面挪出调度器，于是控制面的 O(N) 扫描成了它唯一的性能
  负担。0002 用分片给这个负担加上界。0007 是承认「加上界不等于修好」，以及列出要修什么。
- **0003 → 0005 → 0006。** 0003 给每个租户一个私有域。0005 在存储层加第二道防线，**因为域是
  正确性保障，不是安全边界**。0006 是那个观察的诚实结论：对不可信代码来说进程内隔离根本算不上
  边界，所以它必须离开进程。
- **0004 ↔ 0005。** 两者刻意朝相反方向拉。0004 说请求级状态住在 Go `context.Context` 里；
  0005 说身份**不**住在那儿。分工是：`ctx` 携带「我还能不能继续」，结构体携带「我是谁」。

## 语言

本仓库用两种语言书写，这不是偶然。ADR 记录与代码注释用中文，因为它们记录的推理是用中文做的，
翻译它会让词汇同它所描述的代码脱钩。`README`、`SAFETY`、`BENCHMARK`、`AGENTS` 成对
（`X.md` + `X.zh.md`），因为它们面向两类不同的读者。

符号名、提交信息与本索引用英文。
